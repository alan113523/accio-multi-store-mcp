# 验证说明

## 本公开版本

`pnpm test` 使用临时目录和虚构账号；不读取开发者的 Accio 目录或真实凭据。
Windows 集成测试使用真正的 CurrentUser DPAPI 和官方 SDK stdio 传输，
本地 gateway 和业务返回均为合成数据。

覆盖范围：

- 可变数量的唯一店铺映射，拒绝重复目标。
- 只读工具与严格参数检查，拒绝发布工具、切店参数和非法日期。
- 平台身份结构校验，拒绝缺失、重复或错误主账号。
- 上下文 UTF-8、DPAPI 保存与冻结绑定。
- 交替调用多个通道再返回初始通道，业务前后核对身份。
- 前置 / 后置身份错误、业务拒绝和空响应时不返回业务结果。
- 授权投影、空间、绑定清单变化时停止。
- 官方 SDK 启动独立 MCP 进程，检查工具目录及参数拒绝行为。
- 凭据字段和文本敏感值脱敏。

非 Windows 系统跳过原生集成测试；不能据此宣称支持其凭据或快照格式。

## 原本机实现

发布前的专用实现，在已授权的本地环境中完成过多店铺只读联通测试：
店铺身份、员工经营汇总和上品相关类目元数据。另有独立浏览器关闭时的调用检查。
实测使用 Accio Work 0.35.2，本地 Accio 保持运行。

为保护商家隐私，原始响应、店铺数量、登录名、AliId、员工信息、
经营指标、会话引用、账户指纹、截图及验收日志均不公开。
此说明是维护者对本机测试的范围陈述，读者无法从公开仓库独立重现或审计这些私有结果。

本次公开版本进行了配置化和路径通用化，没有对真实商家重跑业务调用；
合成测试成功不等于任意账号、客户端版本或网络环境已通过平台验收。

## 使用者的最小验收

对每个固定通道执行 `identity`，再执行合法时间范围的 `account_summary`；
检查 `identity.matched` 和 `postIdentity.matched`，并核对实际主账号。
最后回到初始通道，确认没有跟随其他店铺变化。
若要验证退出浏览器后的可用性，应先保存浏览器中的编辑内容，
再退出独立浏览器并记录进程状态，保持本地 Accio 登录运行后查询。

`publishing_categories` 仅测试类目元数据服务，不证明发布写入能力。
服务端可能返回完整类目树，不能把所有节点视作该店铺已开通的类目。
